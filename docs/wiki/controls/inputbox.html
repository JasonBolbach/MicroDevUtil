SuperInputBox

Fixed-format input defined by a template, such as an IP address, a PIN or a licence plate.

Editable (modal edit)src/SuperInputBox.h

What it looks like

Real renders from the library (headless, dark theme, Font2, shown at 2x).

Quick start

SuperInputBox ip(&lcd, 10, 10, 160, &lgfx::fonts::Font2, "###.###.###.###", &Enc, &BtnA, &BtnB);
ip.SetLabel("IP address");
ip.SetValue("192168001010");          // digits only, literals are skipped
ip.SetOnAccept([](void*){ /* ip.GetValue() */ });

Unique features

  • Template characters: # digit, A upper, a lower, B both, * any typeable key. Everything else is a literal: drawn, skipped by GetValue().
  • GetValue() returns only the typed slots ("123456789" for ###.###.###); GetDisplay() returns the formatted text.
  • Short values are padded on the left when every slot is a digit ("42" in ### gives 042), otherwise on the right.
  • SetValidator(fn) can refuse an accept; the edit then stays open.

GUI workflow

Two levels: selecting a slot (encoder moves between slots, text scrolls), then editing the slot (encoder scrolls its characters, wrapping). A short = slot edit / finish slot, A long = accept, B short = cancel, B long = revert and keep editing at the cursor.

Touch: touch a character and it highlights at once; drag up/down changes it; lift accepts. Tap < / > to scroll, tap outside to cancel.

Event workflow

edit contract: OnChange on every character change, OnAccept once after the validator agrees (the stored value is then new).

Main API

CallWhat it does
SetValue(v)Set from typed characters; returns false if it does not fit the template
GetValue()Typed characters only
GetDisplay()Formatted text including literals
SetValidator(fn,user)Veto an accept

Tips and tricks

TipUse a validator for ranges the template cannot express (octets 0-255, a valid month).
TipTouchAcceptOnLift = false gives the older touch style: lift only selects, tap the slot again to finish.

Pitfalls

Watch outA validator that refuses keeps the edit open with no message: show your own hint in OnChange if the user could be confused.
