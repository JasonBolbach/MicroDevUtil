Architecture and class map

Every control draws into its own LGFX_Sprite and pushes itself to the destination (Dst) at (PosX, PosY). Headers depend only on LovyanGFX, SuperGUI's encoder/button classes and the C++ standard library, so the same control runs on a Pico, an ESP32-S3 and the SDL desktop emulator.

The frame every control shares

The base class SuperControl provides everything around the body: border size/colour/style, padding, an optional label (above or below, own font/colour/alignment), colours, SetEnabled, SetVisible, ApplyTheme, DrawPreview. A subclass only implements RenderBody() (and BodyHeight() if the body is not one font line).

Instant, editable, display only

  • Editable controls enter an edit session that ends in accept or cancel (edit contract).
  • Instant controls (check box, radio button, push button) act in StartEdit() and report EDIT_ACCEPTED on the next Service().
  • Display only controls (label, progress bar, graph, gauge) return false from StartEdit(); add them with form.Add(&c, false).

The sprite model

A control renders its whole picture (frame, label, body) into a sprite, optionally dims it, then pushes it in one go. That is why there is no flicker and why labels can be transparent (key colour 0x0001). The price is RAM: width x height x 2 bytes per control. See Memory and performance.
