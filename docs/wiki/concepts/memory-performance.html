Memory and performance

Each control owns one 16-bit sprite: width x height x 2 bytes, where height = font height + 2 x (border + padding) [+ label height]. On a Pico W (264 KB RAM) this matters; on an S3 with PSRAM it rarely does.

SwitchWhat it doesWhen
SuperControl::SharedBuffer = trueOne render buffer, the size of the biggest control, shared by all. Identical pixels, about the same speed.RAM is tight
SuperControl::UseDMA = trueTwo alternating DMA buffers; render the next control while the last one is sent.SPI panels, with SharedBuffer
SuperControl::LabelOpaque = trueSolid label background instead of key-colour transparency (DMA needs it).With DMA
SuperControl::UsePsram = trueAllocate sprites in PSRAM.ESP32-S3 with PSRAM
SetVisible(v, false) + one Form.Draw()Switch pages without a redraw per control. Hidden controls free their sprite.Page changes

Measured (Freenove S3, 80 MHz SPI, octal PSRAM)

Full page redraw 28 ms (was 44 ms); drags about 80 fps; internal heap about 162 KB free with 2 x 78 KB DMA buffers. Slider / progress / graph pushes are about 7 ms each; partial (dirty-rectangle) redraws are not built.

Counters

SuperControl::CollectStats = true accumulates StatDraws, StatRenderUs, StatDimUs, StatPushUs; ResetStats() clears them.

Blank control, only the focus box shows

Sprite allocation failed (out of RAM). The control draws a red outline when it happens. Turn on SharedBuffer or UsePsram, or reduce the number of visible controls.
