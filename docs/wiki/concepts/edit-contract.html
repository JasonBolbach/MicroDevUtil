The edit contract

CallMeaning
StartEdit()Non-blocking begin. Returns false if it cannot edit (empty list, display only...).
Service()Call often. Returns EDIT_ACTIVE while editing, then EDIT_ACCEPTED or EDIT_CANCELLED once, then EDIT_IDLE.
BeginEdit()Blocking wrapper. False if disabled/hidden; true only if accepted.
SetOnChange(fn,user)The value being edited changed (live). List / combo / tabs / menu: the cursor moved.
SetOnAccept(fn,user)Accepted. The stored value is already the new one.
SetAbort(fn)Polled in Service(); returning true cancels (desktop: Quitting()).
StartEdit()→Service() = EDIT_ACTIVE ...→EDIT_ACCEPTED or EDIT_CANCELLED (once)→EDIT_IDLE

The rule that matters most

Stored values change only on accept

While editing, the control works on a copy. GetValue() keeps returning the old value until the user accepts. Cancel (B short) throws the copy away; B long reverts the copy to the start and keeps editing.

Callbacks in detail

  • OnChange fires on every live change: use it for previews (a colour swatch, a volume you want to hear while turning).
  • OnAccept fires once when the edit is accepted: use it to store the setting.
  • Instant controls fire both, OnChange first. The push button has OnAccept only. The radio group passes the new index.
  • Callbacks are plain function pointers void (*)(void* user); pass a captureless lambda and put your object in user.
spin.SetOnAccept([](void* u){ auto* s = (SuperSpinBox*)u; save(s->GetValue()); }, &spin);

Non-blocking loop

spin.StartEdit();
for (;;) {
  SuperEditState st = spin.Service();
  if (st == EDIT_ACCEPTED) { ...; break; }
  if (st == EDIT_CANCELLED) break;
  doOtherWork();
}
