The form file (JSON)

A form is a plain JSON file you can read, diff and edit by hand (or let Claude edit). Only values that differ from the defaults are written.

{ "form": { "name": "Form1", "width": 320, "height": 240 },
  "controls": [
    { "type": "SuperPushButton", "name": "okBtn", "text": "OK", "x": 16, "y": 80, "width": 90 },
    { "type": "SuperListBox", "name": "colors", "items": ["Red", "Green", "Blue"], "selected": 2 },
    { "type": "SuperMenu", "name": "menu1", "items": [
        { "text": "System", "items": [ { "text": "Reboot", "itemId": "MNU_REBOOT", "id": 7 } ] },
        { "text": "About" } ] }
  ],
  "messageBoxes": [
    { "name": "msgDelete", "title": "Careful", "message": ["Delete all data?", "Cannot be undone."],
      "buttons": [ { "text": "Yes", "itemId": "MSG_DELETE_YES" }, "No" ], "default": 1 } ] }

Minimal is enough

  • A menu item can be just "About": on load the designer adds the missing item ID (MNU_ABOUT) and the next free number.
  • A list item is a string. A tab with a page is { "text": "Home", "group": "GRP_HOME" }.
  • A message box "message" can be one string with \n; a button can be a plain string.

Repairs on load

A hand-edited file is checked and repaired, never trusted: unsafe or repeated names are replaced (the first owner of a repeated name or ID keeps it), empty items are dropped, numbers are pulled into range, a selected index past the last item is pulled back, two selected radio buttons in one group keep only the first, non-ASCII characters are dropped. Export refuses a menu, group or message box that still has a problem, and says which.

TipSaving writes the repaired form: open a hand-edited file, look at what changed, and save.
