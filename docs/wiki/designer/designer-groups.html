Lists, menus, tab pages and groups

List box, combo box, tab bar: the items dialog

Click Edit... on the Items (or Tabs) row.

  • Type in Item text: changes apply live. An empty item is refused.
  • Enter in the text field adds the next item: type a whole list with Enter between the entries.
  • Add, Insert, Delete, Move up / down, Sort A-Z, Clear all. Paste lines adds every non-empty line of the clipboard (copy a column from a spreadsheet).
  • Items are printable ASCII, 1 to 60 characters, at most 200. Enter = OK, Esc (in the list) = Cancel.
  • In your code the lists change at run time too: InsertItem, RemoveItem, SetItem, GetItem.

Menu

A menu is a tree. Every command has an item ID (a C++ name that becomes static constexpr uint16_t MNU_REBOOT = 7;) and a number. Edit it in the menu editor (Edit... on the Menu items row).

  • Add adds a sibling, Add child a sub-item; Indent / Outdent change the level; Move up / down reorder.
  • New items get the next free number and an ID made from the text (Power off becomes MNU_POWER_OFF). The ID follows the text until you type your own.
  • Paste outline: every clipboard line becomes an item, indentation (spaces or tabs) makes sub-items. The quickest way to enter a big menu.
  • At most 5 levels and 200 items.

In code the handler is menu1_Choose(uint16_t id):

void menu1_Choose(uint16_t id) override {
  switch (id) { case MNU_REBOOT: Reboot(); break; case MNU_ABOUT: ShowAbout(); break; }
}

Rich text

The Rich text control shows scrollable text with a few HTML-like tags (colours, background, underline, strike, big text, alignment, <tab>, <hr>; see SuperRichText). Its Text row has an Edit... button that opens the rich text editor.

  • Source mode edits the markup as text: arrows, Up / Down keep the column, Home / End, Shift selects, Enter makes a new line, Ctrl/Cmd + A C X V Z, mouse click / drag, double-click = word, triple-click = line, wheel scrolls. The tags you may use are listed under the text.
  • Rendered mode shows the real control with your text (read-only; the wheel scrolls). Switch with the buttons or Ctrl/Cmd + R.
  • Ctrl/Cmd + Enter = OK, Esc = Cancel. Nothing is checked: what you type is what the control gets.
  • In the JSON the text is a readable array of lines: "richText": ["<center>Title</center>", "Some text"]. The generated code uses SetTextStatic(...): a string literal that stays in flash.
  • Other rows: Body height, Tab stops, Line gap, Show source (draws the markup itself, for debugging).

Control groups

Every control has a Control group row: a name (empty = no group). Controls with the same name are a group, and each group becomes a constant GRP_X. Do not confuse it with the radio button's Group, which only says which radio buttons exclude each other.

Form.SetGroupVisible(GRP_ADVANCED, false);   // hide a whole set
Form.SetGroupEnabled(GRP_ADVANCED, true);    // enable / disable a set

Tab pages

In the tab bar's items dialog every tab has a Page group: the control group shown while that tab is chosen. The generated code does the switching (tabs1_ShowPage(i)), then calls your tabs1_Accept(). The first tab's page is shown at start; the other pages start hidden.

Use the View button above the surface to look at one page at a time (All, then each group): only that group's controls, and the ones without a group, are shown and clickable, so pages that overlap on the form can be edited separately.

TipPut controls that appear on every page (a title, a footer) in no group: they are always shown.
Watch outA group operation overrides a control’s own Visible / Enabled: SetGroupVisible(g, true) shows every control in the group, including ones you set to Visible = No. A control that must stay hidden should not share a group with controls that get shown.
