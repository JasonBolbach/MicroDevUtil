Designer tips, tricks and pitfalls

Tips and tricks

TipDesign at 1:1, check at Fit. Press 0 for the true pixel size and F to see the whole form. Everything you see is drawn by the real controls, so a gap or a clipped text on screen is a gap or a clipped text on the device.
TipName controls as you place them. okBtn, cancelBtn, volume make the handlers (okBtn_Click) read like sentences. A prefix such as btn, lbl, chk keeps the Controls-on-form list tidy.
TipLists from a spreadsheet: copy a column, open the items dialog and click Paste lines. For menus, copy an indented outline and click Paste outline.
TipInput box templates: Presets has phone numbers, ZIP codes, dates, times, IPv4, MAC addresses and more. Build makes a template cell by cell. # is a digit, A upper case, a lower case, B any letter, * anything; every other character is a literal, so ###-###-#### is a phone number.
TipGauge: the Zones dialog has Fill 3 bands (green / yellow / red at 60 / 85 / 100 % of the range). Update the needle with load.SetValue(v).
TipGraph: Preview data (Sine / Rising / Noise) only exists so the designer shows something. It is not generated: feed the real graph with trace.AddSample(v).
TipPress ? in the designer for the key list. A Rich text control is a good place for your own help screen: write it in the editor, scroll it with the encoder.
TipTab order: add the controls in the order the user should visit them, or type the numbers in the Tab order row (1, 2, 3 ... or 10, 20, 30 to leave room). Display-only controls (labels, gauges ...) have no tab number.
TipOverlapping controls: select one in the Controls on form list and use Front / Back. The list reads from back (top of the list) to front (bottom).
TipPages: design every page in the same area of the form and use the View button to edit one page at a time.
TipHand edits: the JSON file is meant to be edited. Rename a group, reorder menu items, paste a long message: save, open in the designer and it repairs anything unsafe.

Pitfalls

Watch outEditing Form1.designer.h. It is overwritten on every export. Your code belongs in Form1.h.
Watch outA new handler is not in your file. After you add a control, export and read the status line: it names the handlers Form1.h does not have. Copy the stubs from the protected: list.
Watch outNames are strictly checked. A C++ keyword (class, int), a library or Arduino name (delay, Serial, PI, HIGH), a pin name (A0, D13), a macro defined by the headers, a name starting with an underscore or fd_, or one that ends like a handler (x_Click) is refused. Two things can never share a name: controls, radio groups, menu IDs, control groups, message boxes and their button names, and the form (Form1, Form1Base).
Watch outThe constructor needs both buttons: (dst, enc, btnA, btnB).
Watch outA group show overrides Visible unless the form’s Keep hidden row is Yes: then a Visible = No control stays hidden when its group (or tab page) is shown; ctl.SetVisible(true) shows it.
Watch outText is US-ASCII. Accented letters and symbols outside the printable ASCII range are dropped when typed, pasted or loaded.
Watch outMessage boxes block. _Ask() does not return until the user answers. Use _Open() / _Poll() in a loop that must keep running.
Watch outUser draw cannot be previewed. The designer cannot run your drawing code, so it shows a placeholder. Your name_Draw(spr, body) is what the device draws.

Checking the designer itself

FD_SELFTEST=1 build/FormDesigner runs hundreds of automatic checks with synthetic mouse and keyboard events and exits 0 when all pass. FD_SNAPSHOT=frame.raw writes the first frame (raw big-endian RGB565, 1400x820) and exits; useful for screenshots.
